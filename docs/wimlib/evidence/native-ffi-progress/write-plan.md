Historical writer callback implementation plan

This records the design before implementation. The current implementation and reproduced gates are described in README.md. Original probes refined selection timing: the target receives its initial header before source metadata validation, while dirty image XML statistics refresh before target opening.

The previous buffered facade emitted no write callbacks. `write-red.json` and `write-modes-red.json` preserve 55 unchanged-header original/native comparisons before implementation. `original-join-split-events.json` preserves another 16 original operation sequences. The optional C probe join case requires `-DPROBE_JOIN_PROGRESS`; ordinary compilation stays usable against the current native library without that export.

The replacement writer needs a resource plan, not an eager decompressed staging WIM. Select and validate image metadata first, count referenced hashes, and retain each original encoded resource location with its independent backing owner. Do not read data payloads before the initial stream event. Preserve compressed encoded resources when source/output codec, chunk size, layout, selected solid membership, and recompression flags permit reuse. Decode/recompress only when policy requires it. Original raw resources are checked while copying; final hash checking follows the final completed-stream callback.

Handle mutation phases must use short exclusive borrows before and after callback-bearing work. Selection and writing retain a shared handle borrow; progress uses the interior-mutable registration. Callback code may replace/unregister progress, but may not free the active handle or mutate its resource/image state. File ownership belongs to a separate writer context, not to the handle.

The actual output sink must append bytes before progress callbacks. Abort at the initial stream event leaves an initial header; abort before metadata leaves written data; abort after metadata leaves metadata; abort during integrity calculation leaves XML but no completed integrity table. No later compression, hashing, file bytes or handle finalization may happen after cancellation. Successful completion rewrites the finalized header and applies the requested sync policy.

The safe format serializers should retain no-progress entry points delegating to progress-capable implementations. Resource encoding must expose chunk completion after actual compression and append work, including uncompressed and compressed byte counts. Metadata begin/end callbacks have NULL payloads. Integrity calculation needs its own initial and per-SHA-chunk hooks, with a NULL filename. Pipable order is metadata before streams; ordinary and solid order is streams before metadata. Temporary solid validation/compression must not manufacture events for work that is not part of the actual output.

Registration snapshots follow original phase boundaries: data stream callbacks keep the registration captured before the initial stream event; metadata begin/end reread the handle registration independently; integrity snapshots its registration at entry. Stream payload total_parts counts source parts that supply data rather than the output header's part count.

Join-with-progress can open each source through open-with-progress, validate/sort the complete split set, reference independent resources into the first handle, and call the same writer. The existing eager join serializer cannot establish correct read/callback timing. Split callbacks must surround real individual part writing, permit caller replacement of the part filename, and retain the operation-owned filename when unchanged. Callback state is caller-owned throughout.

Multi-origin ordering must compare GUID and part before physical offsets, preserving the original pointer tie caveat for distinct handles representing the same GUID/part. Ordinary callback success alone is insufficient evidence for encoded-copy, solid, pipable, callback abort or output-file-state contracts.
